# Open-source dictation apps: post-processing pipelines

Research agent report, 2026-09-25 (web sources as cited; claims marked unverified are as the agent flagged them).

Here are the findings. All five repos were fetched directly (READMEs + relevant source files via `raw.githubusercontent.com`, GitHub API metadata via `gh api`, and code search via `gh api search/code`) rather than relying on marketing pages, so claims below are grounded in what the repos actually contain as of 2026-09-25 (all five had commits pushed today, i.e. currently active).

---

## 1. VoiceInk — github.com/Beingpax/VoiceInk

- **Open source**: Yes, GPLv3. 6,560 stars, 927 forks, 147 open issues, ~1,783 commits, pushed 2026-09-25. Note: the LICENSE file itself is a truncated stub ("For the complete license text, please visit: gnu.org/licenses/gpl-3.0.txt") rather than the full legal text, which is why GitHub's own SPDX detector reports `NOASSERTION` instead of a clean GPL-3.0 match ([LICENSE](https://github.com/Beingpax/VoiceInk/blob/main/LICENSE)). The project explicitly does not accept external PRs ("This project is not accepting pull requests at this time" — [README](https://github.com/Beingpax/VoiceInk/blob/main/README.md)).
- **STT models**: whisper.cpp (Whisper), Parakeet via FluidAudio, SenseVoice Small (FunAudioLLM/Alibaba), local GGUF models via TranscribeCpp/transcribe.cpp ([README Acknowledgments](https://github.com/Beingpax/VoiceInk/blob/main/README.md)). Source also wires up cloud STT providers ElevenLabs, Deepgram, Soniox, Speechmatics, AssemblyAI in the same provider enum ([AIService.swift](https://github.com/Beingpax/VoiceInk/blob/main/VoiceInk/Features/Enhancement/State/AIService.swift)).
- **LLM cleanup ("AI Enhancement")**: Yes, a dedicated service ([AIEnhancementService.swift](https://github.com/Beingpax/VoiceInk/blob/main/VoiceInk/Features/Enhancement/Workflows/AIEnhancementService.swift)) that sends the transcript plus a user-editable prompt to a chosen provider: cloud (OpenAI, Anthropic, Gemini, Groq, Cerebras, Mistral, OpenRouter), local (Ollama, "Local CLI"), a custom OpenAI-compatible endpoint, or VoiceInk's own hosted "VoiceInk Refine". Optional context injection: selected text, clipboard, screen-capture OCR.
- **Gating — explicit and documented in source**: `TranscriptionPipeline.swift` reads `SkipShortEnhancement` (UserDefaults bool, **default `true`**) and `ShortEnhancementWordThreshold` (**default 3**, user-adjustable 1–15 in Settings). If enabled and the transcript's word count ≤ threshold (and it isn't a "respond"/assistant-mode request), the AI Enhancement call is skipped outright and the raw/formatted transcript is used as-is. Settings UI copy: *"Skip short transcriptions — Automatically skip AI enhancement when the transcription has very few words. Short phrases like 'yes', 'thank you', or quick commands don't benefit from enhancement."* ([TranscriptionPipeline.swift L163–170](https://github.com/Beingpax/VoiceInk/blob/main/VoiceInk/Features/Recording/Workflows/TranscriptionPipeline.swift), [AppDefaults.swift](https://github.com/Beingpax/VoiceInk/blob/main/VoiceInk/App/Configuration/AppDefaults.swift), [ModelSettingsPanel.swift](https://github.com/Beingpax/VoiceInk/blob/main/VoiceInk/Features/ModelLibrary/Views/ModelSettingsPanel.swift)). This is the clearest length-based LLM-skip heuristic found across all four apps.
- **Custom vocabulary — two separate mechanisms**: (1) "Personal Dictionary" (`CustomVocabularyService`) is injected into the AI Enhancement system prompt, instructing the LLM to correct phonetically-similar transcription errors to the exact listed spelling — this only fires when Enhancement actually runs. (2) `WordReplacementService` ("Smart Replace") is a separate, deterministic find/replace pass applied to every transcript unconditionally, independent of AI Enhancement ([TranscriptionPipeline.swift](https://github.com/Beingpax/VoiceInk/blob/main/VoiceInk/Features/Recording/Workflows/TranscriptionPipeline.swift)).
- **Output sanitization**: `AIEnhancementOutputFilter` strips `<thinking>`, `<think>`, `<reasoning>` tags via regex from reasoning-model output before use ([AIEnhancementOutputFilter.swift](https://github.com/Beingpax/VoiceInk/blob/main/VoiceInk/Core/Enhancement/AIEnhancementOutputFilter.swift)).
- **Streaming**: A `TranscriptionSession.swift` / "streaming session" concept exists in the pipeline signature, but nothing in the README documents a local partial-transcript UI; this more likely serves the streaming cloud STT providers (Deepgram/AssemblyAI/Soniox/Speechmatics all offer live streaming APIs). **Flagged: not clearly documented as a latency-hiding feature.**

## 2. Handy — github.com/cjpais/Handy

- **Open source**: Yes, MIT (brand/logo assets excluded). 32,195 stars, 2,952 forks, 184 open issues, 860+ commits, pushed 2026-09-25. Rust + Tauri v2, cross-platform (macOS/Windows/Linux); originally a Python CLI, since rewritten ([README](https://github.com/cjpais/Handy/blob/main/README.md)).
- **STT models**: Whisper (Small/Medium/Turbo/Large via ggml, GPU-accelerated where available), Parakeet Unified EN 0.6B (GGUF, CPU-optimized, auto language detection), Silero VAD for silence filtering, plus user-supplied custom Whisper GGML models auto-discovered from a local `models/` directory ([README](https://github.com/cjpais/Handy/blob/main/README.md)).
- **LLM cleanup**: Yes, but structured as a completely separate, manually-triggered action rather than an automatic step on every transcription. Two distinct global shortcuts/CLI flags exist: `transcribe` vs `transcribe_with_post_process` ([actions.rs](https://github.com/cjpais/Handy/blob/main/src-tauri/src/actions.rs), `handy --toggle-post-process` per [README](https://github.com/cjpais/Handy/blob/main/README.md)). The LLM call itself is a generic OpenAI-chat-completions-compatible client supporting Apple Intelligence (on-device), a custom base URL (works with local Ollama/LM Studio), or named providers like OpenRouter/Anthropic/DeepSeek ([llm_client.rs](https://github.com/cjpais/Handy/blob/main/src-tauri/src/llm_client.rs), [usePostProcessProviderState.ts](https://github.com/cjpais/Handy/blob/main/src/components/settings/PostProcessingSettingsApi/usePostProcessProviderState.ts)).
- **Gating — the default cleanup path is rule-based, not an LLM at all**: `remove_filler_words()` in [audio_toolkit/text.rs](https://github.com/cjpais/Handy/blob/main/src-tauri/src/audio_toolkit/text.rs) uses a two-tier, explicitly "gated" filler list: a small universal set ("uh", "umm", "hmm"...) is always stripped, while language-ambiguous fillers (English "um"/"ah"/"eh"/"ha", German "äh"/"ähm", French "euh" — real words in other languages) are only stripped when there's separate evidence of the detected output language. Also does stutter-collapsing ("I I I I" → "I") and whitespace normalization, unconditionally. The optional LLM post-processing step is gated by user action (which hotkey/flag is pressed), not by an automatic content heuristic.
- **Custom vocabulary**: `custom_words` are applied differently depending on model family ([managers/transcription.rs](https://github.com/cjpais/Handy/blob/main/src-tauri/src/managers/transcription.rs)): for Whisper-family models they're passed as the decoder's native `initial_prompt`; for non-prompt-taking models (e.g. Parakeet) Handy instead runs a fuzzy post-transcription correction pass (`apply_custom_words`) that matches near-misses against the list. A community Raycast extension exposes "manage dictionary" against the same list ([README](https://github.com/cjpais/Handy/blob/main/README.md)).
- **Streaming**: README documents a strict press → speak → release → batch-transcribe flow ("Release and Handy processes your speech using Whisper"). Source distinguishes "streaming models" internally in the prompt-handling code (comment: "Streaming models do not receive a decode prompt"), but this describes model-internal decoding, not a user-visible live/partial transcript. **Flagged: no documented latency-hiding UI.**

## 3. OpenWhispr — github.com/OpenWhispr/openwhispr

- **Open source**: Yes, MIT. 8,561 stars, 1,059 forks, 376 open issues, pushed 2026-09-25. Electron/React desktop app (macOS/Windows/Linux) plus a separate Expo mobile app in the same monorepo (`openwhispr-mobile/`). Note: many near-identical GitHub search results (fragglexarmy, jrlprost, hiro-nikaitou, cadufpolis, henmedia, rodaddy, egsok) are plain forks/clones of this same org-owned repo, not independent projects.
- **STT models**: Local — Whisper via whisper.cpp; NVIDIA Parakeet and other models via sherpa-onnx (one bundled option branded "Orukeet" in-app); GPU accel via Metal/CUDA/Vulkan. Cloud — Cohere Transcribe, plus Deepgram/AssemblyAI/Corti/Gemini/OpenAI realtime STT integrations (BYOK) ([README](https://github.com/OpenWhispr/openwhispr/blob/main/README.md)).
- **LLM cleanup**: Yes — a dedicated cleanup pass, explicitly distinct from the "Voice Assistant" agent mode. README: the Voice Assistant hotkey sends speech "straight to your AI assistant as a command... **no cleanup pass**" (implying ordinary dictation does get one). Implemented in [`cleanupTranscript()`](https://github.com/OpenWhispr/openwhispr/blob/main/openwhispr-mobile/src/lib/cleanupTranscript.ts), which calls a "ReasoningService" (local llama.cpp or a configured cloud/local provider route).
- **Gating — several explicit, source-confirmed gates, all configuration/quality-based rather than length-based**:
  - Master toggle `cleanupEnabled` (default `true`); if off, returns raw text unchanged.
  - Empty-text short-circuit (comment: sending empty text risks the model echoing its own instructions as fake output).
  - Availability gates: skipped with a user-facing message ("Choose a cleanup provider in AI Models. Your raw transcript is saved.") when no provider is configured, sign-in is required, or the route is unavailable — always falls back to raw text.
  - Timeout/retry: 12s timeout (30s if a voice-assistant mention is detected), one retry, then falls back to raw text on failure.
  - **Output-quality gate** ([`assertValidCleanupOutput()`](https://github.com/OpenWhispr/openwhispr/blob/main/src/utils/cleanupOutput.ts)): detects when the LLM's "cleaned" output is actually a near-duplicate/echo of the input transcript via token-overlap comparison, and rejects it (falling back to raw text) — a genuine automatic check on LLM output quality, not just availability.
  - No word-count/length "too short to bother" heuristic was found (unlike VoiceInk's explicit 3-word default).
- **Custom vocabulary**: A user-managed "Dictionary" ([DictionaryView.tsx](https://github.com/OpenWhispr/openwhispr/blob/main/src/components/DictionaryView.tsx)) feeds both the STT decode prompt and the LLM cleanup call's `customDictionary` parameter ([dictationHints.ts](https://github.com/OpenWhispr/openwhispr/blob/main/openwhispr-mobile/src/lib/dictationHints.ts)). A separate "Snippets" feature ([snippets.ts](https://github.com/OpenWhispr/openwhispr/blob/main/src/utils/snippets.ts)) does deterministic trigger-phrase → replacement-text expansion, with documented Unicode edge-case handling (Turkish dotted/dotless I) and a documented character cap on how much dictionary+snippet text gets stuffed into the Whisper decoder prompt.
- **Streaming**: Multiple realtime streaming integrations exist in source (`deepgramStreaming.js`, `assemblyAiStreaming.js`, `geminiLiveStreaming.js`, `openaiRealtimeStreaming.js`, `cortiStreaming.js`) and the Voice Assistant "streams into a floating panel." **Flagged: not confirmed whether the default local Whisper/Parakeet dictation path itself streams partial words, or only cloud realtime engines/assistant replies do** — docs.openwhispr.com's quickstart page contains no pipeline/gating detail at all; everything above came from reading source directly.

## 4. FluidAudio — github.com/FluidInference/FluidAudio

*(Not itself a dictation app — it's the shared Swift/CoreML ASR+diarization+VAD+TTS engine that VoiceInk, FluidVoice, Hex, Spokenly, BoltAI and ~40 other showcased apps build on.)*

- **Open source**: Yes, Apache-2.0. 2,892 stars, 433 forks, 20 open issues, v0.12.4, pushed 2026-09-25 ([README](https://github.com/FluidInference/FluidAudio/blob/main/README.md)).
- **Parakeet variants shipped**: `parakeet-ultra-coreml` (recommended, 25 languages, "more accurate than v3 at the same speed"), `parakeet-tdt-0.6b-v3-coreml` (multilingual, library default), `parakeet-redux-coreml` (~220MB, iOS18+/macOS15+ only), `parakeet-tdt-0.6b-v2-coreml` (English-only, "highest recall"), plus Parakeet EOU (120M) for streaming with end-of-utterance detection. Batch real-time factor ~190x on M4 Pro.
- **LLM cleanup**: **None.** The only "post-processing" is Inverse/Text Normalization via a companion crate, [text-processing-rs](https://github.com/FluidInference/text-processing-rs) (a Rust port of NVIDIA NeMo Text Processing, "100% NeMo test compatibility, 3,011 tests") — rule-based spoken→written conversion ("two hundred" → "200"), not an LLM. It's optional and droppable (`traits: []` in Swift 6.2+) to save ~8MB per app slice. No gating heuristic exists because there's no LLM step to gate — any LLM cleanup is left to the consuming app.
- **Custom vocabulary/hotwords**: Not documented anywhere in the README or linked docs index.
- **Streaming**: `SlidingWindowAsrManager` for real-time streaming ASR with cancellation support; streaming diarizers LS-EEND (100ms frame updates, 900ms tentative preview, up to 10 speakers) and Sortformer (up to 4 speakers, better identity stability); Parakeet EOU built specifically for low-latency streaming. Latency is hidden via Apple Neural Engine offload, explicitly avoiding GPU/MPS.
- **Maturity**: well-maintained (2.9k★, only 20 open issues relative to size), and its 40+ app showcase list is a strong ecosystem-adoption signal even though it's a library, not an app.

## 5. FluidVoice — github.com/altic-dev/FluidVoice

*(Canonical repo — confirmed via GitHub API metadata; a huge number of same-named repos under other accounts, e.g. gvkhna, KronosMMXM, MarqueIV, hberends2, sanetrawiley-sys, Defake, ben-vargas, praxstack, Mu-L, devadathanmb, EliseiNicolae, are plain forks of this one, several explicitly marked "forked from altic-dev/FluidVoice" by GitHub. Separately, jonathanglasmeyer/FluidVoice is an unrelated, much smaller project with the same name — a naming collision, not a fork.)*

- **Open source, with an important caveat — open core**: The app is GPLv3 since 2026-02-23 (Apache-2.0 before), 11,755 stars, 842 forks, 95 open issues, pushed 2026-09-25. But the flagship LLM cleanup feature, **"Fluid Intelligence," is explicitly closed-source**: *"Fluid Intelligence is a separate, privately maintained local AI runtime... We're keeping Fluid Intelligence private for now so we can sustainably offer the core dictation experience for free."* ([README](https://github.com/altic-dev/FluidVoice/blob/main/README.md)). It runs locally (downloaded separately, ~3.5GB) but its weights/serving code are not in the repo.
- **STT models**: Nemotron Speech 3.5 (~40 languages, ~670MB, "ultra fast low latency") and a higher-accuracy Nemotron 3.5 Multilingual variant (~530MB); Parakeet Flash (beta, English, lowest-latency live dictation, ~250MB); Parakeet TDT v3 (25 languages, ~500MB, default) and TDT v2 (English-only, ~500MB, fastest); Cohere Transcribe (14 languages, ~1.4GB); Apple Speech (built-in); Whisper Tiny→Large (99 languages, Intel-Mac compatible).
- **LLM cleanup**: Fluid Intelligence (closed) handles "smart formatting, context-aware capitalization, and post-processing" on-device; alternatively OpenAI, Groq, or a custom OpenAI-compatible endpoint can be used instead — the gate code explicitly recognizes localhost/RFC1918 addresses as "local" endpoints, so this can point at Ollama/LM Studio. Per-app prompt configuration is supported. The README/marketing cites a self-reported eval: Fluid-1 scores 77.31% on a 10,000-example dictation-cleanup set vs. 56.73% for GPT-5.4 and 34.72% for base Gemma — **self-reported and task-specific, not independently verified**.
- **Gating**: The open-source `DictationAIPostProcessingGate` ([source](https://github.com/altic-dev/FluidVoice/blob/main/Sources/Fluid/Services/DictationAIPostProcessingGate.swift)) gates purely on **configuration/availability** — is a provider selected (not "Off"), and is it verified (a SHA-256 fingerprint of base-URL+API-key must match a stored "verified" fingerprint) — not on transcript content or length. A token-budget parameter (`maxOutputTokens`) is passed per Fluid Intelligence call (confirmed via `PrivateAIDictationTokenBudgetTests.swift`), suggesting output length is capped/scaled, but this is a budget control, not a skip-if-short heuristic. **No word-count "skip short transcript" gate analogous to VoiceInk's was found.**
- **Custom vocabulary/hotwords**: Not documented. "Per-App Configuration" (different prompt sets per app) is the closest personalization mechanism, but it's prompt-based, not a vocabulary list.
- **Streaming**: The most explicitly marketed latency story of the five: "Live Preview" real-time overlay ("see words appear as you speak"), Nemotron Speech 3.5 marketed as "Streaming-capable," Parakeet Flash marketed for "Lowest-latency live English dictation," and a v1.6.0 changelog claim of "pretty much zero delay between speaking and seeing words on screen." The precise mechanism isn't spelled out beyond marketing copy, though FluidAudio's own README lists FluidVoice as built on FluidAudio, so it likely inherits FluidAudio's `SlidingWindowAsrManager`.

## Cross-app summary on your specific questions

| | Gates/skips LLM cleanup? | Mechanism | Fast local model instead of LLM? | Custom vocab | Streaming/partial results |
|---|---|---|---|---|---|
| **VoiceInk** | Yes, explicit, default-on | Word-count threshold (≤3 words skips) | No — rule-based replace runs always; LLM optional on top | Yes (2 mechanisms: prompt-injected + rule-based replace) | Undocumented for local path |
| **Handy** | Yes, but via manual hotkey choice, not automatic | Separate keybinding for "with post-process"; default path is regex/fuzzy-match, no LLM at all | Yes — filler removal + fuzzy word correction are the *default*, LLM is opt-in extra | Yes (decoder prompt or fuzzy post-correction) | Not documented; explicitly record-then-batch-transcribe |
| **OpenWhispr** | Yes, but on config/quality, not length | Toggle, empty-text check, availability check, output-duplicate-detection rejection | No — LLM (local llama.cpp or cloud) is the only cleanup path found | Yes (dictionary + snippets) | Realtime cloud STT providers only; local path unclear |
| **FluidAudio** | N/A (library, no LLM step) | Rule-based ITN only, optional/droppable | Yes — ITN/TN is deterministic, not an LLM | Not documented | Yes — sliding-window ASR + streaming diarizers, ANE-offloaded |
| **FluidVoice** | Yes, on config/verification only | SHA-256 "verified provider" gate; token-budget cap, no length skip found | No — LLM enhancement (closed "Fluid Intelligence" or BYOK) is the only cleanup path; core STT itself is fast/streaming | Not documented | Yes — most explicitly marketed ("zero delay"), live overlay |

The one documented example of gating on transcript *length* specifically (closest analog to your Parakeet+slow-LLM concern) is **VoiceInk's default-on "Skip short transcriptions" (≤3 words)**. Handy is the one app whose *default* cleanup pipeline avoids an LLM entirely, using regex/fuzzy-match rules instead, with the LLM as a separate opt-in action. FluidAudio (the underlying engine several of these apps share) confirms that ITN-style rule-based post-processing is a well-established alternative to LLM cleanup for at least the "normalize numbers/units" sub-problem.
