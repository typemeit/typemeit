# AssemblyAI "note-taking API" — research findings

**Bottom line up front:** AssemblyAI has no product literally named "note‑taking API." The two real, recent things it's likely referring to are the **Dictation API** (shipped Sept 15, 2026) and the **Speech Understanding API** (part of the relaunched LLM Gateway family), both marketed under AssemblyAI's "AI Notetaker" solutions page. Neither takes plain text input, so neither is directly usable for a text‑in/text‑out clean‑up eval.

**1. What exists, endpoints, output**
- **Dictation API** — `POST https://dictation.assemblyai.com/v1/transcribe/live`. One call runs STT + an LLM cleanup pass, returning both the verbatim transcript (`text`) and a cleaned version (`llm_response`): filler removed, self-corrections resolved to what the speaker landed on, punctuation/casing applied. Default behavior can be overridden via `llm_instruction` (free text, ≤2048 chars). Sources: [assemblyai.com/blog/dictation-api](https://www.assemblyai.com/blog/dictation-api), [assemblyai.com/docs/dictation](https://www.assemblyai.com/docs/dictation).
- **Speech Understanding API** — `POST https://llm-gateway.assemblyai.com/v1/understanding` (EU: `llm-gateway.eu.assemblyai.com`). Takes a `transcript_id` + a task (`summarization`, `action_items`, `custom_formatting`, `translation`, `speaker_identification`) and returns structured JSON per task — not a cleaned verbatim transcript. Source: [assemblyai.com/docs/api-reference/llm-gateway/create-speech-understanding](https://www.assemblyai.com/docs/api-reference/llm-gateway/create-speech-understanding).
- The "notetaker" branding ([solutions/ai-notetakers](https://www.assemblyai.com/solutions/ai-notetakers/), [docs/meeting-notetaker-best-practices](https://www.assemblyai.com/docs/meeting-notetaker-best-practices)) is a marketing bundle of the above plus STT — not a distinct API.

**2. Text vs. audio input**
- Dictation API: audio only (WAV/raw PCM, ≤120s/call); no text-in mode ([docs/dictation](https://www.assemblyai.com/docs/dictation)).
- Speech Understanding: requires a `transcript_id` from an already-completed AssemblyAI transcript — audio must already have run through their STT.
- **LLM Gateway** (the actual LeMUR successor) is text‑in/text‑out: `POST https://llm-gateway.assemblyai.com/v1/chat/completions`, OpenAI‑compatible. Auth header `authorization`, value = raw API key, no `Bearer` prefix per their own curl example (their OpenAI‑SDK quickstart, which normally sends `Bearer <key>`, is also shown as working). Body: `{model, messages:[{role, content}], max_tokens, fallback_config, model_region}`. Relaunched May 6, 2026, 20‑25+ models, zero markup. Sources: [docs/llm-gateway/overview](https://www.assemblyai.com/docs/llm-gateway/overview), [blog/reintroducing-llm-gateway](https://www.assemblyai.com/blog/reintroducing-llm-gateway). Model IDs seen: `claude-sonnet-4-5-20250929`, `gpt-5`, `gpt-5.1`, `gemini-2.5-pro`, `qwen3.5-4b-32k-fast`. **Flag: pulled via automated page-summarization and the fuller list included implausible-looking names (`gpt-6-astra`, `claude-opus-5-5`) — verify directly against [docs/llm-gateway/available-models](https://www.assemblyai.com/docs/llm-gateway/available-models) before pinning an ID.**

**3. Formatting/cleanup/custom vocab** — all audio-time only. `punctuate`/`format_text`/`disfluencies` are transcription-request parameters. `keyterms_prompt` boosts custom vocab during recognition (≤100 terms streaming, ≤1,000 pre-recorded, also in Dictation API config). Speech Understanding's `custom_formatting` task likewise only runs against an existing audio-derived transcript. None apply to text that didn't go through their STT. Sources: [docs/streaming/prompting-and-keyterms](https://www.assemblyai.com/docs/streaming/prompting-and-keyterms), [docs/speech-understanding/custom-formatting](https://www.assemblyai.com/docs/speech-understanding/custom-formatting).

**4. Pricing/latency** — Async STT: Universal-3.5 Pro $0.21/hr, Universal-2 $0.15/hr; streaming $0.45/hr. Dictation API: $0.62/hr all-in; latency reported inconsistently ("~134ms" per blog vs. "mean 0.36s" per docs — unreconciled, likely best-case vs typical). LLM Gateway: pass-through token pricing, e.g. Claude Sonnet ~$3/$15 per M tokens in/out, GPT‑5.1 ~$1.25/$10 (verify live). Sources: [assemblyai.com/pricing](https://www.assemblyai.com/pricing), [blog/dictation-api](https://www.assemblyai.com/blog/dictation-api).

**5. Retention/privacy** — Async default: audio deleted in 24-48h, final transcripts auto-delete from 30 days; with a BAA, default drops to 72h, configurable to 1-hour TTL. Streaming gets zero retention if you opt out of model training. **LLM Gateway gets zero data retention only with an executed BAA and Anthropic/Google models** — otherwise logging/billing metadata persists; no plain self-serve opt-out found otherwise. Sources: [docs/faq/how-long-does-aai-retain-data](https://assemblyai.com/docs/faq/how-long-does-aai-retain-data), [support.assemblyai.com/articles/2240096256](https://support.assemblyai.com/articles/2240096256-does-assemblyai-offer-zero-data-retention).

**Recommendation:** The "note-taking API" doesn't apply here at all — both candidate products need audio or a pre-existing AssemblyAI transcript ID, and our eval cases are plain text with no source audio. Score the eval via **LLM Gateway's `/v1/chat/completions`**, sending our own clean-up system prompt (folding in the digits/filler/contractions/lists/quotes options, custom vocabulary, and screen-context terms as instructions) with a pinned model ID confirmed live on the available-models page. This exercises the underlying model directly at zero markup — AssemblyAI adds no transcript-specific cleanup logic on this path, so it's equivalent to calling that model ourselves through a proxy.
