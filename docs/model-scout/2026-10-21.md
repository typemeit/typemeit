## Underdog Bark 3.0 Plus and Pro

- Role: speech recognition. Would replace Parakeet Ultra.
- What it is: Conway Research's English fine-tunes of NVIDIA's Parakeet TDT 0.6B v3, the same architecture as Ultra. Published 2026-10-15 in four builds: Bark 3.0 (163 MB, low-bit weights), Plus (180 MB), Pro (the full bf16 model, 1.25 GB) and Clean (Plus trained to drop fillers, false starts and repeats).
- Claimed numbers, from the [Pro card](https://huggingface.co/ConwayResearch/Underdog-Bark-3.0-Pro): self-run with the Open ASR Leaderboard's scoring code; there is no leaderboard row yet. Seven-set average and AMI-Cleaned: Pro 4.29 / 7.16, Plus 4.76 / 7.76, Bark 3.0 4.94 / 7.82, against the leaderboard rows for Parakeet v3 4.94 / 9.42 and Phonon-2 5.21 / 9.32 (parakeet-tdt-0.6b-v2: AMI 9.09). The card has no Ultra row. Phonon-2 lost to Ultra on our dictations by 1.31 points, so Bark 3.0 at v3's average is not expected to beat Ultra; Pro, and maybe Plus, are the builds that claim to. FluidInference's own Core ML run puts standard Bark 3.0 at 4.96 on LibriSpeech test-other against v3's 4.12, which is worse. Clean scores 4.08 against cleaned DisfluencySpeech references and 12.12 on verbatim AMI, because it removes words by design. Training data is not disclosed, so AMI may be in it.
- Licence and size: CC-BY-4.0, with credit to NVIDIA, Moondream and Conway Research. Pro's Core ML package is about 1.23 GB (FP16), under the 1.5 GB file budget; its resident memory is unmeasured and may pass the 1.5 GB dictation budget. Plus is 180 MB. Bark emits `<unk>` where its training text had quotation marks; FluidAudio strips it from #1054 on.
- Provenance: Conway Research, the maker of the Underdog dictation app (underdog.ai), which runs these models on Mac and iPhone through MLX. Created 2026-10-15, last updated the same day. Base model `nvidia/parakeet-tdt-0.6b-v3` on the card. Pro ships its own Core ML runner built on FluidAudio, loading with `version: .ultra`. [FluidInference/bark-3.0-coreml](https://huggingface.co/FluidInference/bark-3.0-coreml) (created and updated 2026-10-21) repackages Bark 3.0 and Clean in FluidAudio's v3 layout. Third-party GGUF, sherpa-onnx and ONNX builds exist. Downloads and likes: Pro 65 / 9, Plus 8 / 6, Bark 3.0 12 / 18, Clean 0 / 25.
- Used by: Underdog. Code search finds no other repository.
- Eval to run: `make asr-eval` against the Universal-3.5 Pro references. Pro's Core ML package and Plus load through `Scripts/asr-eval/fluidasr`'s `orukeet` mode (`AsrModels.loadLocal`, v3 layout); copy `systems/fluid_orukeet.py`. Run Pro first, since it carries the claimed gain, and measure its resident memory against the 1.5 GB dictation budget. Fluid Speech Mini made a similar self-run claim of parity with Ultra and lost by 0.58 dictation points on our references (2026-10-17).

## Granite Speech 5.0 2B (over the 1.5 GB file budget)

- Role: speech recognition. Would replace Parakeet Ultra.
- What it is: IBM's speech model, released 2026-10-20. A Conformer audio encoder feeds Granite 4.0 1B, which writes the transcript; 2.31B parameters, six languages, and it takes a keyword list of up to 2,000 terms. The 470M TurboCTC model tried on 2026-09-30 is a different architecture.
- Claimed numbers: a leaderboard row since 2026-10-19, run by the maintainers. Average 5.06 against parakeet-tdt-0.6b-v2's 6.43; AMI-Cleaned 6.96 against 9.09; Earnings-22 6.22 against 6.76. AMI (150 h) and Earnings-22 (105 h) are in its training data, so neither is a held-out number. Granite Speech 4.1 2B NAR claimed the same AMI 6.96 and lost on our meetings by deleting stretches of speech (2026-10-16). [Model card](https://huggingface.co/ibm-granite/granite-speech-5.0-2b).
- Licence and size: Apache-2.0. The official GGUF is Q4_K_M 1.14 GB plus a 1.16 GB audio projector (2.3 GB), or Q8_0 1.96 GB plus the projector. Over the 1.5 GB file budget at every published size. The card says to cut audio into pieces of about two minutes.
- Provenance: IBM Granite. Repo created 2026-10-07, last updated 2026-10-21; GGUF repo created 2026-10-14. Built on `ibm-granite/granite-4.0-1b-base`. 105 downloads, 23 likes (GGUF: 177 downloads).
- Used by: no repository found by code search beyond IBM's own.
- Eval to run: `make asr-eval` through llama.cpp's GGUF, with a `systems/` file copied from `granite_nar.py`. It cannot ship within the file budget, so run it only if the budget is reopened.

## FluidAudio 0.17.6: offline diarizer fixes

Not a model, but it changes the speaker pipeline we ship (pinned 0.17.5):

- [#982](https://github.com/FluidInference/FluidAudio/pull/982): `embedSpan` tiles a short span to fill the WeSpeaker window instead of zero-padding it. On 1–4 s spans the right-centroid rate rose from 25–36% to 98%. `Diarizer.voice(of:)` in `TypeMeIt/Meetings/Diarizer.swift` copies the zero-padding on purpose, to match `embedSpan`, so the learn-voices clips would need the same change.
- [#988](https://github.com/FluidInference/FluidAudio/pull/988): digitally silent frames are left out of the FBank mean, which stops muted call tracks and the zero-padded last window from making extra clusters.
- Eval to run: bump to 0.17.6 and run `make asr-eval ARGS=score` for wrong-speaker words, and re-run the voice-names test from `docs/voice-names-research/` with tiled clips.

## Near misses

- FluidInference/bark-3.0-coreml standard and Clean builds: the standard build is worse than v3 on LibriSpeech test-other in FluidInference's own run; Clean drops words on purpose, so it cannot be scored against verbatim references.
- phequals/qwen35-2b-muesli-cleanup-v12-gguf: a LoRA fine-tune of Qwen3.5-2B for dictation clean-up (Apache-2.0, 1.31 GB Q4_K_M), scored only on synthetic test sets. Qwen3.5 2B is rejected in `model-trials.md`; its LFM2.5-1.2B sibling uses the LFM Open License.
- freetranscribe/parakeet-ft-v1: a Parakeet v3 fine-tune that stops long recordings losing passages; its own card says it is worse on meeting speech, and it was created 2026-10-13, before the window.
- arbazsiddiqui/voxlock: a 27M voice-isolation model that keeps one enrolled speaker; a pre-transcription stage, not a role we ship a model for. ONNX only, about 1.4× faster than realtime on an M2 Pro CPU.
- qvac/TranscribePsy-250M-EU: a 254M distillation of Parakeet v3; leaderboard average 8.02, worse than Parakeet.
- desert-ant-labs/voz: source-available licence; leaderboard average 7.40.
- MiMo-V2.5-ASR (Xiaomi, runnable in mlx-audio 0.6.0 from 2026-10-19): 7.6B parameters, 32 GB in bf16, mainly Chinese, no leaderboard row.
- inclusionAI/Ming-3.0-asr-tiny: about 8.9B parameters, Chinese-first, no Apple Silicon runtime, English numbers only in an image.
- AuroraAI-Research/AuroraASR-1M: 11.4 WER on LibriSpeech test-clean.
- raj7676/ivy-dictation: Commons Clause licence, no WER.
- futo-org/asr4all-l-plus: futo-ethical-use licence; released before the window.
- h2oai/h2o-lightning-4b (llama.cpp support 2026-10-21): answers one-token decisions only, so it cannot rewrite or summarise.
- FluidAudio 0.17.5's CAM++ embedding, FSMN-VAD and SenseVoice-Small: trained on Mandarin, with no English score.
- Voxtral Small and Mini Transcribe 3 (Mistral, 2026-10-20; AA-WER 2.09 and 2.22, above ElevenLabs Scribe v2 and AssemblyAI Universal-3.5 Pro): the API no longer returns word timestamps, so they fail the eval reference filter.
- Fun-Realtime-ASR-preview (Alibaba, AA-WER 1.73): a realtime preview with no batch API for a 1-hour file.
- nvidia/NVIDIA-Nemotron-3.5-Bolt-74B-A9B-24GB, RecursiveSI/flint, Muse Glimmer 30B: no clean-up score, and too large to run beside the app.
