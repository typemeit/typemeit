## Eval reference: AssemblyAI-STT-3.7 (cloud)

- Role: eval reference (paid, cloud). Would replace AssemblyAI Universal-3.5 Pro, which AssemblyAI deprecated on 2026-11-17. It has no retirement date yet. After retirement, requests naming `universal-3-5-pro` go to STT-3.7 without notice, so the references would change under us.
- What it is: AssemblyAI's new pre-recorded speech-to-text model, launched 2026-11-17 as the successor to Universal-3.5 Pro. It ships with a new speaker diarization model. It covers 32 languages, up from 18. AssemblyAI does not say how it is built.
- Claimed numbers ([benchmarks](https://www.assemblyai.com/benchmarks.md), vendor-run, every vendor's production API at default settings, STT-3.7 measured November 2026, others October 2026):
  - Verbatim-reference WER: mean 6.53% against 7.97% for Universal-3.5 Pro. AMI (headset) 8.17% against 12.76%. ElevenLabs Scribe v2 scores 10.12% on AMI.
  - Speaker-attributed WER (cpWER): mean 24.22% against 26.66%. AMI 21.59% against 26.19%. Scribe v2's mean is 26.41%.
  - DER: mean 12.05% against 12.20%. AMI is worse, 21.05% against 19.41%.
  - Clean-reference WER: mean 5.15% against 4.99%, slightly worse.
  - AssemblyAI's [model notes](https://www.assemblyai.com/llms/models.md), on internal sets: cpWER 29.3% → 24.0%, DER 14.7% → 10.4%, speaker-count error 0.57 → 0.20.
  - Training data is not disclosed, so whether AMI is held out cannot be checked. It has no independent numbers yet: no Voice Arena row and no Open ASR Leaderboard row.
- Price and model id: $0.21 per audio hour, the same as Universal-3.5 Pro. Model id `assemblyai-stt-3-7` (`speech_models: ["assemblyai-stt-3-7"]`). It is the same API, so a 1-hour file still goes in one request with speaker labels and word timestamps.
- Changed defaults: `disfluencies` and `format_text` both default to `true` on STT-3.7, and Universal-3.5 Pro used different defaults. `Scripts/asr-eval/assemblyai.py` sets neither, so set both explicitly before building references. Experimental diarization is not offered on STT-3.7.
- Provenance: AssemblyAI (San Francisco, speech-to-text API company), [announcement](https://www.assemblyai.com/blog/introducing-assemblyai-stt-3-7). It replaces Universal-3.5 Pro (launched before 2026-10-17, when we moved to it).
- Who uses it: `gh search code "assemblyai-stt-3-7"` finds livekit/agents (15,274 stars), livekit/agents-js and pipecat-ai/pipecat (17,320 stars).
- Eval to run: the eval-reference check from the skill. Run `ASSEMBLYAI_SPEECH_MODEL=assemblyai-stt-3-7` on the 12 meeting tracks and 50 dictations, then have the user judge the spans where it and Universal-3.5 Pro disagree (`listen-review` skill). Also score its speaker labels with `make asr-eval ARGS=score`, since cpWER is where its claimed gain is largest. Cache both sets of references: Universal-3.5 Pro results can no longer be re-made once the model retires.

## Clean-up: LvW-Dictate-Cleanup-0.9B

- Role: clean-up. Would replace Apple Foundation Models in `TypeMeIt/PostProcessor.swift`, or sit behind the same gate.
- What it is: a 0.9B text model, published 2026-11-17 by Hugging Face user Lucasgitguy-co, that removes fillers, repeats, false starts and self-corrections from a transcript and fixes punctuation and capitals. It is IFM's K2-Horizon-0.9B with a LoRA fused in, trained on Phonon-2.5 transcripts. A check after the model puts back any deleted words that are not fillers, repeats or self-corrections, and falls back to the transcript if the model adds a word. The cleaned text is therefore made only by deleting words.
- Claimed numbers ([card](https://huggingface.co/Lucasgitguy-co/LvW-Dictate-1.5B), self-run, all test sets held out from training): DisfluencySpeech test (250 clips), WER against the human clean transcript 16.49 → 7.06; FLEURS English 6.49 → 6.50; LibriSpeech test-clean 1.79 → 1.93; dictated questions and commands returned as the cleaned prompt rather than answered, 99.0% (96.8% on unseen validation prompts); 0 words added on all four English sets. The deletion-check rules were tuned on test-set errors, as the card says.
- Licence and size: Apache-2.0 (base K2-Horizon-0.9B is Apache-2.0). 1.08B parameters; GGUF Q4_K_M 666 MB, Q8_0 1,149 MB; both inside the 1.5 GB file budget.
- Provenance: Lucasgitguy-co on Hugging Face (no affiliation stated), created and last updated 2026-11-17; base model [IFM/K2-Horizon-0.9B](https://huggingface.co/IFM/K2-Horizon-0.9B) (2026-09-01, 12,096 downloads, 105 likes); training data published as `Lucasgitguy-co/lvw-dictate-cleanup`; MLX training on an M4 MacBook Air. The model has 2 downloads and 0 likes. The GGUF repo also bundles Phonon-2.5, which is seen and not a candidate.
- Who uses it: `gh search code "LvW-Dictate"` finds only model-listing datasets. Too new to have users.
- Eval to run: `make eval` (Scripts/cleanup-eval), with the card's deletion check and with our guards, as the Phonon refiner trial on 2026-11-06 did. Loads in llama.cpp (GGUF) or mlx-lm. Compare speed against the 500 ms p95 budget; the Phonon refiner (1.7B) ran at p95 2,749 ms, so this smaller model is the main question on speed.

## Clean-up: Fleet-Clean tagger (0.31B)

- Role: clean-up. Would replace Apple Foundation Models for filler and restart removal; it cannot do the rewrites the model does now.
- What it is: a word tagger published 2026-11-17 by Lucasgitguy-co. It is the encoder of convaiinnovations/laya-multilingual (mmBERT) with a new head that decides, for each word, keep or delete, which punctuation mark follows, and whether the first letter changes case. It never writes a word of its own. It ships paired with Fleet-2, a 56M Cactus Whistle speech model; the tagger takes any transcript.
- Claimed numbers ([card](https://huggingface.co/Lucasgitguy-co/Fleet-Clean-0.36B), self-run): DisfluencySpeech test (250 clips), WER against the cleaned transcript 18.8% → 14.6% on Fleet-2 output; punctuation F1 0.6700 → 0.6695; on fluent English (FLEURS, 100 clips) it deletes 0.47% of words. It has no comparison against an LLM clean-up and nothing on Parakeet output. Training data `Lucasgitguy-co/fleet-clean-tags`; whether DisfluencySpeech test is excluded is not stated.
- Licence and size: Apache-2.0 (tagger base and Fleet-2 are Apache-2.0). 307M parameters; GGUF Q8_0 341 MB, F16 629 MB.
- Provenance: same publisher as above, created 2026-11-17; base [convaiinnovations/laya-multilingual](https://huggingface.co/convaiinnovations/laya-multilingual) (2026-09-19, 8,720 downloads, 427 likes). The model has 0 downloads; the GGUF has 18.
- Who uses it: none found; `gh search code "Fleet-Clean"` matches unrelated projects.
- Eval to run: `make eval`, tagger only, on our transcripts. A tagger should be far below the 500 ms budget; the question is accuracy, since it cannot do the rewrites some cases expect. No Swift runtime loads an mmBERT token classifier today: run it through the card's Python script for the eval, and treat a Core ML conversion as the work to do only if it passes.
