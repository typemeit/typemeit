# Model scout 2026-11-20

No new model passes the filters. The finding is a FluidAudio release.

## FluidAudio 0.18.4

- Role: speech recognition and diarization runtime. Would replace the 0.18.2 pin in `project.yml`.
- What it is: FluidInference's Swift package that runs Parakeet Ultra and the offline diarizer on the Neural Engine. 0.18.4 came out on 2026-11-19 ([notes](https://github.com/FluidInference/FluidAudio/releases/tag/v0.18.4)). 0.18.3 (2026-11-07) was text-to-speech only. No new speech or diarizer model.
- Changes on paths the app runs:
  - Long-form v3 (#1111): a window that ends in a pause keeps its sentence-final punctuation. Meeting chunks are up to 120 s (`Fixed.meetingChunkSeconds`), and `AsrManager.transcribe` cuts those into windows internally, so this applies to meetings. It may also apply to dictations over one window.
  - Resampling (#1134): `transcribe(url)` and `transcribe(samples)` now resample the same way, set by `ASRConfig.resamplerQuality` (default `.balanced`). The app passes samples that are already 16 kHz, so this should change nothing. A run should confirm that.
  - Offline diarizer (#1148): `embedSpans` releases Core ML outputs after each batch. The issue was reported on iOS, where memory grew with every meeting. `Diarizer.swift` uses `OfflineDiarizerManager`, so peak memory on long meetings may fall.
  - Downloads (#1150): a cached compiled bundle that is missing its program or weights is downloaded again instead of crashing Core ML on load.
- Changes the app does not use: Nemotron streaming encoder v2 for M2/M3 Neural Engines, vocabulary-boosting floors (boosting was tried and not shipped), Parakeet EOU `rearm`, Cohere ja/zh chunking, tdtJa, TTS (Paradee 1.3, Kokoro), NemoTextProcessing 0.3.4.
- Claimed numbers: none for English Parakeet or the diarizer. The only accuracy number is Cohere's Japanese FLEURS CER, 20% → 3.8%.
- Licence: Apache-2.0, as before.
- Eval to run: the same check as the 0.17.6 → 0.18.2 bump on 2026-11-05. Run `make asr-eval` on meetings and dictation with `run shipped`, measure dictation latency, peak memory and words under the wrong speaker (`nemotron_app`). Expect identical words apart from sentence-final punctuation at window ends, which WER ignores, and a lower diarizer peak.
